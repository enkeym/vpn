# Аудит раскрытия origin-IP — 2026-11-03/04

## Итог

Обещать, что VPN «никак не светит IP», нельзя: VPN использует общий публичный IP для прямого VPN и CDN, а direct DNS и внешний VPN exit позволяют обнаружить адрес VPS. Без отдельного адреса/сервера связь не убрать. В проверенных VLESS-подписках сам IP не найден; HTTP-redirect на IP не обнаружен. Найден дефект авторизации в старых Telegram callbacks. Локальное исправление DNS sync ещё не развёрнуто.

## Проверенные пути

- Подписки с User-Agent Happ, Hiddify, NekoBox и v2rayNG; без User-Agent; явные `format=base64`, `format=singbox`; полный `/full` конфиг. Публичные запросы вернули HTTP 200 без редиректа и без origin IPv4 в теле. Все опубликованные URI — VLESS WS+TLS через CDN-домен.
- Формат по коду: Happ и NekoBox получают base64 со ссылкой `vless://`; Hiddify — sing-box JSON. `format=` явно выбирает base64 или sing-box. Focused resolver suite: 12/12 тестов прошли. Проверена совместимость схемы sing-box с валидатором в ходе прежнего аудита.
- Happ официально принимает обычную web subscription и VLESS; Hiddify документирует v2ray/base64 и sing-box subscription; NekoBox документирует share links, V2Ray subscription и full sing-box JSON. Фактический импорт в UI каждого приложения на устройстве не запускался.
- Проверены старые кнопки/инструкции AWG и основные выдающие функции, peer ownership, QR/config пути, семейные/оплатные выдачи, IPv4/IPv6 listeners и firewall, DNS-поведение, автоматическая синхронизация при старте. Публичные пробы обхода CDN с разными SNI/Host и поддельным `CF-Connecting-IP` не вернули содержимое защищённых endpoint; результат не заменяет полный сетевой аудит всех адресов и исторических источников.

## Подтверждённая уязвимость

В старых Telegram callback обработчиках VLESS меню/QR/файла peer name из callback использовался без серверной проверки владельца перед выдачей ссылки или медиа. Локально добавлена общая проверка owner/admin для callback путей с именем peer: просмотр, включение/пауза, удаление, продление, автопродление, замена, QR, config-файл, VLESS меню и JSON. `cancel_edit_description` оставлен только для администратора. Регрессионные тесты проверяют отказ чужому пользователю на VLESS QR и mutation callback, а также доступ владельца и администратора. Изменения локальные; не опубликованы и не развёрнуты.

## DNS sync

Повторное применение старого DnsSyncService проверено с несколькими A/AAAA и конфликтом CNAME: лишние записи могли пережить синхронизацию при статусе успешной операции. На deployed `e8c452e` startup sync задавал CDN A значение `PUBLIC_IPV4`; в момент проверки CDN и direct уже использовали один адрес, поэтому видимого изменения не было. Локальная правка для CDN обрабатывает все A/AAAA/CNAME, сохраняет их адреса/цели и включает proxy; если записей нет, создаёт A на текущий адрес. Для direct имён синхронизирует A. Регрессионные тесты покрывают A/AAAA/CNAME. Изменения локальные; не опубликованы и не развёрнуты.

## AWG отключён на VPS

2026-11-04 по прямому запросу пользователя выставлен `AWG_ENABLED=false` в `/root/vpn/.env`, контейнер пересоздан с существующим образом без сборки и публикации кода. До изменения AWG действительно работал: интерфейс `awg0` был поднят и UDP 51821 слушал. После пересоздания и ещё одной проверки через 30 секунд: контейнер healthy, `awg0` отсутствует, процесс `amneziawg-go` отсутствует, UDP 51821 закрыт, UFW allow rules удалены для IPv4/IPv6. SSH-доступ сохранился. AWG config на диске оставлен.

Операционный нюанс: `scripts/bootstrap-host.sh` снова добавляет входящее UFW-правило UDP 51821 при повторном запуске, даже с `AWG_ENABLED=false`. Сам сервис при выключенном флаге интерфейс не поднимает.

## Ограничения и следующий шаг

- Direct DNS и VPN exit раскрывают общий IP; отдельный IP/сервер остаётся необходимым для устранения этой связи.
- DNS history и старые уже выданные пользователям AWG/VLESS сообщения не удалялись. AWG config на VPS сохранён.
- DNS sync и callback проверки локально исправлены; изменения не опубликованы и не развёрнуты. Focused Jest: 2 suites, 14/14 тестов; `nest build` и Prettier прошли.
- Импорт подписок в реальных UI-клиентах на физическом устройстве не проверен.
- Старые Reality/VLESS подключения остались без изменений; UFW правило удалялось только для AWG UDP 51821.
